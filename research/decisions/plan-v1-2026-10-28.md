- PC 理論原文逐字保存（`research/pc-theory/theory.md`），實作對應全部寫成待確認假說 H0–H5、H-M1、H-ID（`research/pc-theory/hypotheses.md`）。
- 兩個模型端點實測：
  - DeepSeek `deepseek-flash`（V4.1-Flash，1M ctx，文字＋影像，top-k logprobs，thinking 預設開、可用 `thinking.type=disabled` 關閉）、`deepseek-v4-pro`。使用者剛提供的**新金鑰與 `~/.config/temir/secrets.env` 裡的不同**，已驗證可用。

使用者決定：Rust 優先；CLI＋Web；**DeepSeek API 為預設**，本機 API 用來**確保系統不綁定特定模型**；Web 用 Vite＋TypeScript SPA；個體沒有預設名字／人格（卡莉歐碧只是參考）；PC 理論只能以假說形式落地。

## 研究結論 → 架構決定

| 決定 | 依據 |
|---|---|
| **生命日誌（event sourcing）是唯一真相來源**：對話、工具、內部念頭、預測、評價、自我修訂全部只增不改；記憶、技能、人格紀錄都是投影 | DSH「model-visible means logged」；WikiSkill `raw/` 不可變；Dream-RSI「歷史即環境」；RRSI 編輯帳本 |
| **Rust 插件核心重現 Cordis 語意**：服務倉庫、`inject` 依賴解析、5 種事件派發（emit／waterfall／parallel／serial／bail）、可逆 effect、fiber 生命週期；行程外插件走 MCP | DSH `vendor/cordis/src`、`docs/architecture.md` |
| **PC 循環疊在 turn/step 迴圈上**：perceive→deliberate→prepare→act 四段都寫成事件（假說 H0），自我狀態是個體自己寫的可追溯紀錄而非分數（H1） | 使用者 PC 理論；`hypotheses.md` |
| **記憶三層**：原始事件 → 編譯知識（事實／經歷／看法／自我模型／感受評價）→ 技能；行動時取回的記憶與整合期用的完整知識庫分開 | WikiSkill 三層＋消融（推論 agent 看 wiki 反而差）；Dream-RSI（歷史抽象成提示反而差）；Hindsight 事實／看法分離（不採其 S/L/E 數值） |
| **經驗決策**：JitRL 優勢修正放在 prepare 階段；回報依個體自己的價值評估並記錄評估時的自我狀態版本 | JitRL 方法＋logit vs prompt 消融；本專案延伸見 `methods/jitrl.md` |
| **自我改進分三種情境**：有驗證集→WikiSkill 閘門；開放世界→Harness² Propose–Probe–Compose；任何永久修改→RRSI 帳本＋雜訊下限＋成本規則；策略調參→Dream-RSI 式在日誌上重播 | 四篇論文；Harness²「無對照直接改會變差」 |
| **檢索先用詞彙＋結構＋時間**（SQLite FTS5），embeddings 之後再加 | JitRL 狀態表示消融（文字優於 embedding）；兩個 API 目前都沒有 embeddings |
| **模型無關**：所有測試對 DeepSeek 與本機模型各跑一次；模型差異（thinking 控制、logprobs 位置、工具格式）封裝在 adapter 的能力探測 | 使用者要求；實測差異 |

**不做**：固定人格數值或更新公式；以服從／討喜作為成熟度指標；用 mock 當驗收；把 DSH「架構相似」當成「功能已有」。

版本（crates.io 2026-10-28 查證）：tokio 1.54.1、axum 0.8.9、rusqlite 0.41.0（bundled）、reqwest 0.13.5、clap 4.6.7、rmcp 3.8.0、serde_json 1.0.154、tracing 0.1.44、tower-http 0.7.1、uuid 1.29.0、time 0.3.55；之後視需要 tantivy 0.27、portable-pty 0.9、wasmtime 50。建置產物放 `~/.cache/temir/target`（`scripts/env.sh`）。

**執行形態**：`temir daemon` 是個體的「身體」（長駐：事件日誌、agent 迴圈、排程器、API）；`temir chat` 與 Web 都是連到 daemon 的客戶端（chat 也可內嵌 daemon 單機執行）。個體的閒置認知與整合期只在 daemon 內發生。

## 生命日誌核心事件（M0 就定案，之後只增不改）

`turn/step` 邊界、`user/message`、`assistant/message`（含完整串流）、`tool/call`、`tool/result`、`request/header`（模型、參數、prompt 組成）——對應 DSH 持久事件；
加上 PC 四段：`perception`（來源：external／internal）、`deliberation`（候選行動＋各自的預期後果）、`preparation`（選定行動、明確預測、用到的經驗與自我狀態版本）、`action`、`outcome`、`appraisal`（感受描述＋重要程度：日常／值得注意／重大／轉折，可對舊事件重新評價）、`revision`（自我模型／價值／目標／敘事的修訂，含觸發來源 internal／external 與原因事件）、`model/switch`。

系統提示不寫人格，只組裝**處境描述**（它是什麼、有哪些工具、它自己寫的自我模型目前版本、它可以拒絕）。自我模型初始為空。

## 里程碑

### M0　身體（本次核准後立即執行）
1. 更新 `~/.config/temir/secrets.env` 為新金鑰（repo 外；建議之後輪換，因金鑰出現在對話中）。首個 commit：研究文件、`CLAUDE.md`、`WORKLIST.md`、session log。
2. `temir-kernel`：Context／service／inject／events／effect／fiber；單元測試涵蓋 5 種派發、依賴等待、卸載反序釋放。
3. `temir-store`：schema、append、依 session 投影訊息歷史、FTS5；測試：重放一致、`kill -9` 後恢復。
4. `temir-llm`：OpenAI 相容串流＋tool calls＋logprobs；啟動時能力探測並寫入事件（logprobs？thinking 可關？影像？）；對本機模型自動採用 prefill `<think></think>` 取未推理分布；`temir probe` 指令輸出探測報告。
5. `temir-tools`＋`temir-agent`：fs／shell 工具、管線、turn/step 迴圈、PC 四段事件（deliberation 與 preparation 先由同一次模型呼叫結構化輸出，之後 M2 拆開）。
6. `temir-server`＋`temir-cli`＋`web/`：SSE 即時串流；CLI chat；Web 對話＋事件時間軸。
7. 端到端驗收（兩個模型各一次）：完成一個多步工具任務；Web 即時看到同一 session；中途 `kill -9` 恢復；logprobs 探測如實記錄。

### M1　記憶與 PC 紀錄（`temir-memory`）
- 投影層：事實／經歷／看法（連到來源事件）／自我模型／目標／感受評價（H1、H-M1）；行動時的取回（結構＋FTS5＋時間）；整合期（閒置或指令觸發）：評價新經歷、重新評價舊事件、提出修訂、記錄穩定性／適應性候選量（H5，只觀察不設硬門檻）。
- 實驗：固定探針情境 + 消融（移除自我狀態／移除感受評價）比較選擇分布；結果寫入 `experiments/`。

### M2　經驗決策（`temir-learn`）
- JitRL：回合後評估器產生逐步回報（評估標準＝個體自己的價值與目標，記錄自我狀態版本）、折扣回報、狀態抽象、Jaccard／FTS 鄰居、$\hat V/\hat Q/\hat A$、正規化、logit 修正（token-level 編號法；黑箱時口述信心並標明）。
- Dream-RSI 式重播：在已記錄的決策上評估不同 $k,\beta,\lambda$ 與取回規則，只在支撐集內。

### M3　技能、插件、自我改進（`temir-skills`、`temir-evolve`）
- 技能目錄（SKILL.md＋PURPOSE.md，多 root 探索）、MCP client、插件管理（行程外插件）。
- WikiSkill 迴圈（個體有可驗證任務集時）；Harness² Propose–Probe–Compose＋`EXPERIENCE.md` 函式庫（開放情境）；RRSI 帳本、$\delta$ 校準、成本規則、退火預算作為所有永久修改的閘門。個體可以為自己寫技能與插件。

### M4　自主性與對齊項目
- 自主目標與排程（閒置認知）、拒絕與異議的紀錄；身份連續性實驗（切換 DeepSeek↔本機，比較自我敘事與探針選擇，H-ID）；依 `research/dsh/feature-matrix.md` 逐項補 Harness 能力（subagent、jobs、compaction、sandbox、PTY…）；Telegram／LINE／Discord 作為插件。

## 驗證

- 每個 crate：`cargo fmt --check`、`cargo clippy -D warnings`、`cargo test --workspace`；測試替身只在單元測試並標明。
- 端到端一律用真實 API，**對 DeepSeek 與本機模型各跑一次**，結果（含失敗）寫入 `research/log/<date>-sNN.md`。
- 每個研究主張附 TeX 節號或 `file:line@commit`；`references/*` 的 HEAD 必須等於 LOCK。
- M1 起每個「人格／記憶在參與決策」的主張都要有消融數據，沒有數據就寫「未驗證」。

## 誠實邊界

- DSH 全部能力（388 套件、61 萬行）需要多個工作階段；以 feature-matrix 逐項追蹤，不以架構相似充數。
- PC 假說全部待使用者確認與實驗檢驗；穩定性／適應性的候選量在實驗前只作觀察。
- 本機模型無法關閉 thinking，用 prefill 繞過，屬於已標示的近似。
- 「超級智能」是研究問題；個體若日後放棄追求更高智能，依使用者定義仍算成功。
