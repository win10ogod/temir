## 1. 來源

- **DSH 0.2.2-rc.1**：npm 的 `latest`（`next` 是 rc.2、`alpha` 是 alpha.3）。裝在 `~/.cache/temir/dsh-runtime`，Node 要求 `>=24.9.0`。
- **和 alpha.2 的差別**：比較兩個執行期的 node_modules。
  - cordis 4.0.6-alpha.1 → 4.1.0，schemastery 3.18.6-alpha.1 → 3.19.0，`dsh-*` 都是 0.2.2-rc.1。
  - 移除 dsh-computer-use、dsh-cua、dsh-cua-bundle；新增 dsh-client-ui-context-menu、dsh-client-ui-file-actions、dsh-fs-patch。
- **插件用到的事件**：rc.1 的型別宣告都還有。
  - `agent/pre-step` 的 payload 仍有 `messages`。
  - `system-prompt/assemble` 不再有工具陣列（dsh-system-prompt README：「the presentation waterfall receives no tool array」）。
- **兩處引用在 rc.1 的同一行仍成立**：
  - `dsh-client-connection` lib/index.js:276（token 參數）；
  - `dsh-llm-deepseek` lib/index.js:2019（totalTokens）。
- **上游 DSH Tavern**（flizzywine/dsh-tavern）：
  - 2.3.0（5039205）對應 DSH 0.1.x；3.3（09a66711）對應 0.2.x，dsh-mnemon 0.5.31。
  - 3.3 的 `tavern-plugin/lib/host/tools.js` 是 0.2.2 的工具宣告相容層。
- **範圍**：F:\DSH 裡的 DSH 插件。
  - GitHub 上的 8 個：agent-browser、auto-tool-prune、evidence-first-knowledge-work、fount-memory、fount-reality、knowledge-work、tavern-room、turn-continuation；
  - 個體：temir repo；
  - 只在本機的 dsh-kiseki-input。
  - 其他沒有 git 的資料夾是技能或筆記，不是 DSH 插件：dsh-wsl-claude-skill、dsh-wsl-codex-skill、claude-codex-plugin、pi-plugin-task。

## 2. 已驗證的能力

- **六個一般插件**（做法同 s14 的 alpha.2）：
  - peer 加上 0.2.2-rc.1、cordis `~4.1.0`；schemastery 加上 `~3.19.0`；devDependencies 改成 rc.1；版本加一；README 的版本句。
  - 在 ext4 的工作目錄安裝並跑各自的 check。
  - `pnpm update` 會改寫範圍與鍵的順序，已改回原本的範圍與順序，再以 frozen lockfile 重跑。
- **agent-browser**：版本照原本的命名改為 `0.38.1-dsh.0.2.2`（發布時由上游 tag 決定版本）。
- **整合包形狀的 profile**：rc.1、DSH_HOME 是 `~/.cache/temir/dsh-home-rc1`，bundles 為 dsh-base、dsh-web-app 加上全部插件。
  - 用 tarball 安裝，`--dump-config` 沒有略過任何插件。
  - 模型指向本機的測試替身 `fake-llm.mjs`（OpenAI 相容、一律回固定的話）。
  - 測試的 shell 拿掉 DeepSeek／OpenRouter 金鑰，所以不會有付費呼叫。
  - 開 Web 之後，只有 agent-browser 沒啟用：repo 版沒有 linux-x64 原生檔，原生檔由它的發布流程建置。
  - 第一次只放 dsh-base 時，fount-reality 與 knowledge-work 的 preset 在等 `agentPresets` 服務；這個服務由 dsh-web-app 提供。
- **tavern-room**：
  - npm 的 prerelease 規則使 dsh-mnemon 的 peer 範圍 `>=0.2.1-rc.1 <0.3.0-0` 不接受 0.2.2-rc.1（ERESOLVE）。
    - 用 `legacy-peer-deps` 要手列十多個間接的 peer，改用 `overrides` 指定 typert-protocol 與 app-boot 為 rc.1。
  - 用 Playwright（WSL 的 Chromium）跑頁面檢查：開頁、酒館、人物卡、世界書、設定、功能目錄 API（8 個啟用）、開局與歷史、匯入測試卡、開新遊戲、一個故事回合。
  - 第一次故事回合失敗：`session/prompt` 被接受，但回合以 `Cannot read properties of undefined (reading 'filter')` 結束，沒有任何模型請求。
    - 原因：`foreground-orchestration-strategies.js` 與 `background-agent-task.js` 在 assemble 裡篩選 `assembly.tools`，0.2.2 沒有這個陣列。
  - 修正：照上游 3.3 的 `host/tools.js`，與上游同一份檔案，記在 `vendor/upstream/UPSTREAM.json` 的 backports。
    - 從該步准入的工具（`ctx.tools.schemas(agent, context.toolSet)`）開始篩選；
    - 結果在 `llm/stream`、tools guard 與 `tools/pre-execute` 生效；
    - 世界書篩選任務的工具限制從 `agent/request` 移到這裡，因為 0.2.2 的 `agent/request` 不能改工具。
  - 修正後，故事回合送到模型（16.6 KB 的請求），回覆顯示在對話中，頁面錯誤 0。
  - 停止伺服器時出現一次 `退休后台会话释放失败 … flush on a closed handle`，是關閉時後台 session 已關。
  - 舊的頁面檢查腳本（`scripts/browser-smoke.mjs`，9 月）找的「功能模組」標題只在舊的 `public/app.js`，現在的頁面沒有，不是退步。
- **個體**：
  - 把 repo 的 `node_modules/@deepseek-ai` 暫時連到 rc.1，typecheck（含 experiments）與兩組測試都通過，再換成正式的執行期。
  - 以替身模型在 rc.1 的 headless 跑一回合：所有插件載入、生命日誌正常。
    - `rd/deliberation-failed` 是因為替身不呼叫 deliberate。
- **執行期的切換**：
  - 舊的 alpha.2 改名為 `~/.cache/temir/dsh-runtime-0.2.2-alpha.2`；
  - 39 個凍結 worktree 的連結改指向那裡（它們當時就是在 alpha.2 上跑的）；
  - `setup-dev.sh` 加上版本檢查（以前只看有沒有 `dsh`）。
