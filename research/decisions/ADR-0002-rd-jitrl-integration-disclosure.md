## D1　記憶的按需披露

依據：
- Claude Code 的 MEMORY.md 索引＋按需讀取（經 hr98w `src/index.ts:86-88`@06823e0）；
- jipika 的地圖模式（`index.js:494-517`@2ca0b15）。

做法：`temir-recall` 新增 `disclosure: 'full' | 'progressive'`。

- **progressive**：
  - 新 session 的「關於對方」與「最近一次對話」照舊；
  - 相關片段中分數最高的 `expand` 筆（預設 3）呈現全文，其餘只列一行索引（id、日期、要點）；
  - 個體需要細節時，用 `recall` 工具的 `ids` 參數展開。
  - 因為索引行便宜，自動回憶的上限在此模式提高到 16 筆。
- **full**：維持 c6c363e 的行為。

預設值由實驗決定。v2 的證據是「自動帶入」對隱性運用很重要，所以不採用完全不帶全文的做法。

**2026-10-29 更新**：dev2（v2 題目已暴露，只作診斷）中，progressive 在兩個模型上的記憶主要比較都不低於 full（DeepSeek 0.957 vs 0.894、Nemotron 0.979 vs 0.915），注入字數少約三成。依 dev2 規格 §3 改為預設，`disclosure: full` 仍可設定，實驗條件 `temir-full`。正式比較仍是 E-D1。

**2026-10-29 第二次更新**（使用者：「按需披露還能優化」）。依 dev2 實際注入的內容分析：
- 約 980 字（15%）花在完整的事件 id 上，而個體幾乎不用 id 展開（DeepSeek 63 題中 1 次、Nemotron 0 次）；
- 索引的 13 行中，大多是「關於對方」已經列出的事實；
- 「關於對方」每行都重複日期；
- 「我當時表達的立場與承諾」多半與回答本身重複；
- 「關於對方」只取最新的 2400 字：生命越長，舊而重要的事實（例如過敏）越會被擠掉，而且個體不知道有東西沒列出。

修正：
1. 回憶與索引顯示短 id（`f8998337#34`、`l:350cc6a4`）。`LifeStore.resolveId` 解析回完整 id：只有恰好對應一個事件時才算數。`recall`、`self_revise`、`narrate`、`appraise` 都接受短 id。
2. 索引不重複「關於對方」已經列出的事實。
3. 「關於對方」依日期分組。
4. 按需披露時，全文片段只留「我當時的結論」（擷取時規定先寫結論）。
5. 「關於對方」的上限內，前一半先給與目前線索有共同檢索詞的事實，其餘依新到舊補滿；沒列出的註明條數，需要時用 recall 找。

## D2　RD 階段（H0：思考後回饋、行動準備與預測）

新插件 `temir-rd`。每個含有對方新訊息的 pre-step 依序做：

1. **事後比對**（背景執行，不阻塞回覆）：
   - 本 session 上一個決定的預測，與實際發生的事比對。實際發生的事包括我實際說了什麼、對方接著說了什麼。
   - 輔助呼叫依我目前的自我模型評估這個結果（reward ∈ [−1, 1]），寫出差異與教訓，記為 `rd/outcome`。
2. **思考與準備**（同步）：輔助呼叫產生處境描述 s 與 3 個候選行動，每個候選附上預期後果與 0–100 的口述信心。
   - 輸入：自我狀態、自動回憶的內容、對方的話，以及過去類似處境的經驗。
3. **經驗修正**：用 JitRL（D3）修正候選的分數，選出行動。
4. **準備訊息**：把處境、候選、預測、選擇與相關經驗，以內部訊息（`temir-rd`，不建立回憶索引）放在對方的話之後，主模型據此行動。主模型可以在行動時改變主意，事後比對會記下實際做了什麼。
   準備只給方向，不寫內容（dev2 的教訓）：候選的 action 寫做法而不列舉事實；準備訊息不帶思考時的記憶摘要，並註明回應的內容以回憶與對話為準。原因是 dev2 中，準備把一個要列出全部醫囑的問題框成只有膝傷，回覆漏掉了回憶裡有的另一項。
5. **紀錄**：`rd/decision` 記下候選、分數、修正量、鄰居、選擇與自我模型版本。`rd/*` 不進一般回憶，只供 JitRL 與整合期使用。

## D3　JitRL 經驗修正

論文：arXiv:2601.18510，`method.tex` §3.2–3.3；超參數見 `appendix.tex` 表 tab:jericho_hyperparameters。

| 步驟 | 論文 | 本專案 |
|---|---|---|
| 記憶 | (s, a, G) | `rd/decision`（s、選定的 a）＋`rd/outcome`（r） |
| 回報 | $G_t=\sum_{u\ge t}\gamma^{u-t}r_u$（eq:discounted_return） | 同一 session 內依決定順序計算；遇到沒有 r 的決定就截斷。γ＝0.5（Jericho 值） |
| 狀態表示 | 精簡、結構化，「功能相同的狀態映射到相似的表示」（`method.tex`〈State Construction〉） | 思考時以固定欄位寫處境：對方、意圖、情緒、話題、相關的記憶；不寫個體自身狀態的套話。e2e-13 的自由文字處境中，兩次相似的傾訴相似度只有 0.15–0.23 |
| 狀態相似度 | Jaccard（Jericho 門檻 0.95、WebArena 0.8） | 兩條路徑的聯集，取前 k＝10。兩條都是**本專案的選擇**，門檻之後以重播調整：<br>① 只對意圖、情緒、話題三欄的檢索詞算 Jaccard，門檻 0.2。欄位標籤、對方描述與相關記憶不算，否則無關的處境也顯得相似。<br>② 思考時列出的過去經驗中，模型判定為同一類處境者（`similar`）。e2e-14 中，字面相似度區分不了同一類的傾訴（0.09–0.16）與無關的請求（≤ 0.06）。 |
| 行動相符 | $a_i=a$ | 同類別，且行動描述的 Jaccard ≥ 0.35（**本專案的選擇**） |
| $\hat V$、$\hat Q$ | 鄰居 G 的平均（eq:value_est） | 同 |
| 未見過的行動 | 機率 λ 給 $\hat V+\alpha/\lvert N(s)\rvert$，否則 $Q=0$（eq:exploration） | 同；λ＝0.65（Jericho）。α 改為 1，因為我們的 G 在 [−2, 2] 之間，α＝5 會讓探索壓過所有經驗（**本專案的選擇**） |
| 優勢 | $\hat A=\hat Q-\hat V$，除以 $\max\lvert\hat A\rvert+\epsilon$ | 同 |
| logit | token 對數機率，或口述信心「轉成 logit」（`experiments.tex` 〈Verbalized Logit〉） | 模型不提供 logprob 時用口述信心：$z=\ln(c/\sum c)$（論文沒有給轉換式，這是**本專案的選擇**） |
| 更新 | $z'=z+\beta\tilde A$（eq:logit_update） | 同；論文沒有給 β 值，取 β＝1（**本專案的選擇**） |
| 選擇 | 論文：依 softmax 取樣；參考程式：argmax | argmax（同參考程式） |
| 記憶專屬行動 | 加入候選，基礎 logit 0 | 不另外加入；改把鄰居的行動與結果放進思考提示，讓模型自己提出（與論文 Jericho 提示中的參考行動清單同一做法） |

**與論文前提的衝突**：論文的一致性定理假設回報分布平穩，但個體的價值會改變。每個 `rd/outcome` 都記下評估時的自我模型版本，整合期可以依新價值重新評估（之後實作）。

## D4　整合期與自我修復（H5、H4）

新插件 `temir-integrate`。

**觸發**：
- **啟動時到期**：距離上次整合超過 `intervalHours`（預設 24 小時），且新經歷達到 `minEvents`。在背景執行；未完成就不推進排程，下次啟動重試。
- **轉折**：個體把某段經歷評為「轉折」後，下次整合以深度模式進行（H4）。
- **主動**：個體自己呼叫 `integrate` 工具。

**流程**：
1. **收集**：上次整合以後的經歷（回合摘要）、感受、RD 的預測誤差與回報、目標變化、目前的自我模型、關於對方的長期事實、既有的教訓。
2. **提出**：以個體最近使用的模型提出結構化 proposal，包括：
   - 教訓（附證據 id）；
   - 對過去經歷的重新評價；
   - 自我模型修訂（附理由與原因事件）；
   - 目標變更；
   - 已過時的長期事實；
   - 未解的矛盾（s1）；
   - 自我演變的敘述（s2）。
3. **驗證**：以確定性程式碼驗證（參考 hr98w `consolidation-proposal.ts`、topics-memory `consolidate.ts:14-28` 的安全模型）：
   - 所有引用的 id 都必須存在；
   - 目標操作只能針對既有目標，新增除外；
   - 自我修訂必須引用至少一個經歷；
   - 不合格的項目丟棄並記錄。
4. **寫入**：都是新增事件：
   - `memory/lesson`，可被回想；
   - `appraisal`，帶 reappraisal 標記；
   - `self/revision`，trigger＝internal；
   - `goal/change`；
   - `memory/outdated`，`personFacts` 不再列出過時的事實。
5. **觀測量（只記錄，不作為門檻，H5）**：
   - a1：預測不符的比例；
   - a2：目標變化；
   - a3：平均回報；
   - s1：未解矛盾數；
   - s2：修訂引用的經歷數。

   s3（重複探針的一致性）需要探針，之後再做。
6. **紀錄**：`self/integration` 記下範圍、觸發來源、proposal 原文、套用與丟棄的項目、觀測量；敘述文字可被回想。

## D5　其他修正（同一批）

`appraise` 工具省略 `about` 時，原本會掛到「本 session 最近一則有文字的 user/message」，在 DSH 中那多半是 runtime-context 或 time-context。v2 的日誌中，15 筆感受**全部**掛在注入的內容上，因此回想時從來沒有帶出感受。改為掛到對方實際說的最後一句話。

## D6　人格固有敘事（使用者 2026-10-29）

使用者以 surfcore 為反例：人格由人寫的人格卡套上去，「根本沒有人格固有敘事」，見 `research/dsh/memory-plugins-survey.md` §2.1。

做法：新增 `self/narrative` 紀錄，內容是個體用第一人稱寫的人生敘事，說明自己經歷了什麼、怎麼變成現在的樣子，並引用經歷的事件 id。

- **初始**：創造者給了初始人設的背景故事時，從它開始，見 D8；否則是空白。
- **書寫**：個體可以隨時用 `narrate` 工具書寫或改寫完整的新版本，舊版本保留。整合期的 proposal 也可以提出新版本。
- **帶入**：每一步的自我狀態快照都附上目前的版本（ST 的條件之一）。
- **與自我模型的分工**：自我模型回答「我現在是誰、在乎什麼、傾向怎麼做」；敘事回答「我怎麼變成這樣」。
- **假說**：見 hypotheses.md H-N。

## D7　輔助呼叫的字體檢查（同一批）

e2e-14 中，線索理解把繁體的話擷取成簡體的事實（「对方表示刚才的建议不太想听」）。這些事實經由回憶進入主模型的上下文，主模型的回覆也跟著出現簡體字。

做法：所有輔助呼叫共用 `callModel`。輸入可看出是繁體、輸出卻有 ≥ 2 個簡體專用字時，加註後重試一次（`recall/script.ts`），不做簡繁轉換，因為一對多的字無法可靠轉換。生命日誌以 `retried` 記下是否重試。

## D9　所有修訂途徑都要兼顧穩定性與適應性（性質 6）

- 整合期的 PC 修訂（自我模型、人生敘事、目標）：個體就每一項判斷穩定性與適應性（holds、理由、證據 id）。兩者都成立而且有證據才採用，否則保留為 `self/proposal`。
- 直接修訂（`self_revise`、`narrate`、`goal`）：必須寫出兩項理由，缺一不可，否則工具回報錯誤。這些工具不要求證據 id，以免干擾即時的自我修訂；判斷仍由個體自己做。目標也是 PC 的一部分（H1）；e2e-17 中，個體直接用 `goal` 新增目標，沒有經過判斷，因此一併要求。
- 深度整合（H4）回顧整段生命（受各類上限約束）；一般整合只看上次整合之後的經歷。

## D8　初始人設：PC 的初始狀態，可在循環中改變（使用者 2026-10-29）

使用者：「我一開始就說過了可以給予其初始人設，但這是可在循環中改變的可變項，你似乎嚴重的誤解了。」

先前的實作把個體從「沒有預設名字、身份或人格」開始，這是我對「卡莉歐碧不是指定的人設」與「不用固定系統提示強制人格」的過度解讀。依理論性質 1（PC 並非完全固化），初始人設就是 PC 的初始狀態：

- **設定**：`temir-self` 的 `persona`（`name`、`selfModel`、`story`），或以 `TEMIR_PERSONA_FILE` 指向 JSON 檔。
- **寫入**：只在生命還沒有任何自我修訂時寫入。原樣保存為 `self/persona`（origin body），並寫成自我模型第 1 版（trigger external，原因「創造者給予的初始人設」）；有背景故事時，也寫成人生敘事第 1 版。
- **修訂**：之後和其他版本一樣，可以由 `self_revise`、`narrate` 或整合期修訂。已經修訂過自己的個體，不會被後來的設定覆蓋。
- **不進入固定的系統提示**：人設在自我狀態快照裡，來源是生命日誌。處境描述只說明「創造者給了你初始人設，它是起點、不是限制」。
- **不預設內容**：沒有給的話照舊從空白開始；人設的內容由使用者提供。

## D10　能量：動能與勢能（H-E；使用者 2026-10-29）

使用者說明：「能量在理論中代表的是動能與勢能」。對應見 hypotheses.md H-E。只從既有紀錄推導，不計算數值。
- **勢能**：快照中的「懸著的事」（`self/energy.ts`）。
- **動能**：RD 思考寫下的 `drive`。
- **轉換**：事後比對的 `released`、`left`。
- **整合期**：看得到上次留下的矛盾與保留的提案，可以重新提出。這同時修正了 D4 的一個缺口：保留的提案原本下次整合看不到。
