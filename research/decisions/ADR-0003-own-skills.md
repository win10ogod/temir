# ADR-0003：個體寫給自己的技能（plan v2 M3）

- 日期：2026-10-29
- 狀態：已實作。單元測試與 e2e-24（DeepSeek）驗證。技能是否讓行為變好，還沒有預先登記的實驗（hypotheses.md H-S）。
- 觸發：使用者 2026-10-29：「盡可能全力改善並實現原始設計的要求」。plan v2 的 M3（技能與自我改進）原本完全沒有開始。
- 參考但沒有採用的：使用者給的兩個「給 DSH 靈魂」的插件。
  - `Mieksido/surfcore@d7f6b33`：角色由人寫的人格卡定義（見 `research/dsh/memory-plugins-survey.md` §2.1）。
  - `cyanwell/dsh-agent-soul@504d2d0`：8 個說明與體檢工具，以及給人填寫的 SELF.md 模板；README 明說「不注冊任何改變 agent 行為的鉤子」。
  - 兩者都沒有「個體從自己的經驗改變自己的做法」的機制。

## 決定

1. **技能是「怎麼做」，不是「我是誰」。**
   - 技能是某一類事具體怎麼做的說明（能力）。
   - 人格的修訂（自我模型、看法、敘事）仍走整合期的穩定性／適應性判斷（H5），不用這裡的閘門。這是 RRSI 筆記中「RRSI 只管能力」的劃分（`research/methods/rrsi.md`）。
2. **生命日誌是唯一的真相來源，DSH 技能是投影。**
   - 提案、探測、決定都是只增的事件：`skill/proposal`、`skill/probe`、`skill/decision`、`skill/review`、`skill/use`。
   - 採用中的技能由 `ownSkills()` 從帳本算出，再以 DSH 的執行期技能註冊（`ctx.skills.register`，`dsh-skill` 型別定義）。
   - 主模型在 DSH 的技能目錄（`<available_skills>`）看到名字與說明，需要時用 `skill` 工具載入內容。
   - 這是 WikiSkill 消融的結論：行動中的 agent 看技能，不看整理用的知識庫（`research/methods/wikiskill.md`）。
3. **提案的兩個來源，每次一個原子提案**（WikiSkill 附錄 Algorithm 1 第 3 步）。
   - `skill_propose`：個體自己提出新增、修改或移除。
   - 閒置時的回顧（`REVIEW_SYSTEM`）：上次回顧以後有 2 條以上新教訓時觸發。輸入有：
     - 目前的技能；
     - 帳本，對應 WikiSkill 的 skill-impact，被否決過的提案看得到；
     - 新的教訓；
     - 結果最好與最不好的經驗。
4. **閘門：Propose–Probe–Compose**（Harness² §Task-Level Recursion）。
   - **Probe**：
     - 最多 2 個過去的處境，提案證據直接指到的優先，其餘依詞彙相似度。
     - 每個處境各產生一次「沒有技能」與「有技能」的回覆；修改既有技能時，對照的是目前版本與提案版本。
   - **Compose**：
     - 由個體自己判斷 adopt、revise 或 reject，每個理由都要指出處境與看到的差異；沒有具體觀察的 adopt 當作 reject。
     - revise 的版本是新的提案，要再對照一次才能採用（Harness² 的序列遞迴）。每次回顧最多再一輪，對應 RRSI 的編輯預算。
   - **沒有處境可以對照就不採用**：Harness² 的負面證據是，沒有參考執行與探測就直接修改 harness，表現會變差（Code 73.4→63.2）。
5. **帳本**（RRSI eq:history 的對應）。每筆記下：
   - 元件：skill；
   - 假說：提案的 purpose；
   - 新舊內容；
   - 成本：內容字數的變化，近似 ΔC；
   - 是否採用與理由；
   - 閘門種類：contrast＝行為對照，**未經量測**。個體沒有可重複評估的任務集，量不出雜訊下限 δ，所以 RRSI 的雜訊下限與成本規則無法計算。
   - 確定性驗證：
     - 名字要符合 DSH 的規則；
     - 長度上限；
     - 最多 20 個技能（目錄每一步都進入上下文）；
     - 同樣內容被否決過就不能再提。
6. **使用紀錄**：主模型載入自己的技能時記一筆 `skill/use`。回顧看得到用過幾次，可以據此提出移除，對應 RRSI 的結構修剪；目前沒有自動修剪規則。

## 本專案的近似（與論文不同之處）

- **探測不是在同一個環境重跑任務。** 以生命日誌中過去的處境重建輸入，即思考時寫下的處境與對方的話，加上目前的自我快照，再以輔助呼叫產生回覆。這是行為對照，不是正確性驗證，也不是完整的 DSH 回合（沒有回憶、工具與準備訊息）。
- **合成者與執行者是同一個模型。** Harness² 的消融顯示，同一模型兼任仍有提升，但這裡沒有獨立量測。
- 輔助呼叫使用模型可用的最低推理等級（`recall/aux.ts`）。

## 驗證

- **單元測試** `individual/test/skill.test.ts`（7 項）。模型呼叫是標明的測試替身，涵蓋：
  - 解析與驗證；
  - 探測處境的選擇；
  - 閘門的採用、移除、修改後再對照、沒有處境可以對照；
  - 回顧的輸入。
- **e2e-24**（DeepSeek，計時縮短的測試設定），對話裡對方兩次說「只想抒發」：
  - 個體在第二段對話中**自己**呼叫 `skill_propose`，提出 `listen-without-fixing`。閘門以兩個過去的處境對照，個體依「有技能的版本把發話權交回對方」等具體差異採用。
  - 技能出現在下一個請求的 `<available_skills>` 中，之後被主模型載入 2 次（`skill/use`）。
  - 閒置回顧提出修改：依兩次 −0.40、一次 +0.70 的回報，要求連承接語都不說。對照後個體先要求修改；修改版再對照時，個體判斷它把「有時」固化成通則、不採用，原版本保留。

## 沒有做的

- **個體寫插件**：已在 ADR-0005 實作（創造者核准每個版本）。
- **量測閘門**：WikiSkill 的驗證集與 RRSI 的 δ，只能用在個體有可驗證任務集的情境。
- **技能是否讓行為變好**：skills-v1（預先登記，[報告](../../experiments/results/skills-v1-report.md)）KA FAIL。
  - 個體自己寫了技能、也用上了，但對方明說過的偏好也在回憶裡，拿掉技能也做得到（12/12）。
  - 個體從結果中自己歸納的做法，還沒有檢驗。
