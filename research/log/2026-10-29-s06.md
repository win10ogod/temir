### Web 的內在狀態面板（temir-panel）
- DSH 的 Web 介面插件要有預先打包的瀏覽器程式（client.js）；我們的 bundle 沒有建置步驟。
- 改用 DSH 的 `dsh-host-webserver`：插件可以在同一個伺服器上註冊自己的路由（WebServer.register）。
- 頁面：`/temir/` 是與 `scripts/temir.sh state` 相同的狀態（共用 `self/view.ts`），另有生命日誌時間軸與回憶搜尋。
- 只回應本機請求，並檢查 Host 標頭：DSH 自己的頁面對沒有信任標記的請求回 401，它有防 DNS rebinding 的檢查，面板也比照。
- 真實的 `dsh web --port`：
  - 本機 200；假冒 Host（evil.example）403；

- 指令事故：我用 `pkill -f "port 18766"` 停 dsh web，比對字串打中了執行這條指令的 shell 本身（結束碼 144）；dsh web 沒有殘留。之後改用 `timeout`。

### IM 通道改用 dsh-im（使用者：「更建議直接用這個插件」；ADR-0006）
- `xmanrui/dsh-im@e84df70`（v5.8.0，MIT）有 13 個渠道、主動投遞、會話同步，比我寫的 Telegram 橋接完整，橋接已移除。
- 安裝：`dsh plugin --profile web add -w @xmanrui/dsh-im@5.8.0`，先在測試用的 DSH_HOME、再在正式的 web profile。
- 接合：
  - IM 上的訊息是 `source.kind = 'user'`，個體照常處理；
  - 會話同步不轉送 temir-thought 發起的回合，所以加了 `imTargets`，經 `ctx.dshIm.send` 送出主動開口。
- 安全：dsh-im 在 IM 上顯示核准時看不到插件的程式碼，所以有 dsh-im 時，插件改在本機面板 `/temir/plugins` 核准。
- 真實的 `dsh web`：
  - 個體與 dsh-im 一起載入；
  - 面板顯示「已載入，還沒有接入機器人」；投遞 API 回 `unknown-bot`；
  - 跨站核准 403，本機核准 303 並記下 `via: panel`。
- 真的在 IM 上對話：要等使用者接入機器人。
