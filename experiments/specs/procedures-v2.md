# procedures-v2：做法的修改方向是不是來自經歷（2026-10-31，執行前寫定）

- **問題**（procedures-v1 的結論）：三個個體各自採用的思考做法修改，內容分別落在各自的對方要的方向上，但那只是逐字描述。
  同一個模型在不同的處境中本來就會寫出不同的文字；要知道修改的方向是不是來自經歷，需要同一段歷史重複幾次，
  比較同一段歷史之內與不同歷史之間的差異。
- **假說**：`research/pc-theory/hypotheses.md` H-P（做法屬於個體自己，在經歷中修訂）。這裡檢驗的是「修訂帶著經歷的資訊」：
  只看修改的內容，能不能認出個體和哪一種對象相處過。
- **受測的實作**：與 procedures-v1 相同（ADR-0008 閘門第二版、念頭的排程）。procedures-v1（a134975）之後個體程式的改變只有
  context 模式的重試（f70eec3）與消融的過濾（以句子為單位，只在關掉機制時作用），`temir` 預設路徑沒有改變。
- **這不是效果的驗證**：不判定修改讓行為變好。

## 設計

- 資料集：procedures-v1-a、-b、-c（不改；三種對象的反應方式見各自的 `meta.simulatedUser.rule`）。
- **每段歷史重複 3 次**：run id 前綴 `proc2r1`、`proc2r2`、`proc2r3`，共 9 格，`temir` × deepseek-flash，
  執行器設定同 procedures-v1（`--layout home --assistant-text all`；資料集的 `meta.integrateBetween`：每段對話之後整合）。
  9 格從同一個凍結的 worktree 平行執行，commit 寫在報告中。
- procedures-v1 的三格（`proc1`）只列入描述性的表，不進判定：這個實驗的問題是看了它們之後才提出的。

## 判讀規則（看結果前寫定；`experiments/eval/procedures-v2.ts`、`lib/procedures.ts`）

**前提**：同 procedures-v1（每段歷史完整、沒有回合錯誤；每段歷史之後都有整合期的結束紀錄）。不完整時照實記下，不重跑；
不完整的格照常分析，報告中標明。

**修改的內容**（兩個判定共用）：個體最後的做法與第一版的差異，以句子為單位（個體可能把做法寫成一整段）。
- 新的句子：與第一版的每一句都不接近（二元組的重疊係數 < 0.7）；
- 在原本的句子中加入的片段（改寫的句子與第一版最接近的那一句的字元差異；只縮短、刪掉例子的改寫沒有加入的片段）；
- 整句拿掉的第一版句子（HP4 才列）。

| id | 問題 | 規則 |
|---|---|---|
| HP4（主要） | 只看修改的內容，能不能認出個體和哪一種對象相處過 | 對每個最後的做法與第一版不同的個體，judge（deepseek-v4-pro，thinking disabled，temperature 0）看三種對象的反應方式（順序以 run id 為種子固定打亂）與這個個體的修改內容，選一種。單尾精確二項檢定（對 1/3）p ≤ 0.05，**而且**答對的個體來自至少兩段不同的歷史：PASS；否則 FAIL；這樣的個體少於 3 個：INCOMPLETE。判定失敗算答錯。 |
| HP5（次要） | 修改的文字是不是同一段歷史之內比較像 | 新的句子與加入的片段，兩兩的二元組 Jaccard 相似度；同一段歷史之內的平均減去不同歷史之間的平均。置換檢定（所有保留組大小的標籤排列）p ≤ 0.05：PASS；否則 FAIL；沒有同一段歷史的一對或沒有不同歷史的一對：INCOMPLETE。 |

- judge 只看反應方式，不看人物設定（職業、名字），避免只靠話題比對；提示詞要它看修改的方向，不要只看話題。
- 第二個條件擋住 judge 的偏好：例如 judge 總是選同一種，而只有那一段歷史的個體採用了修改。

**結論的寫法**：
- HP4 PASS：修改的內容帶著經歷的資訊：只看修改，就認得出個體和哪一種對象相處過。這不代表修改讓行為變好。
- HP4 FAIL：沒有證據顯示修改的方向來自經歷（可能是修改太少、太籠統，或 judge 認不出）。
- HP5 只是文字層面的分化：可能來自對話中的具體話題，單獨 PASS 不代表方向來自經歷。

**描述性**（不作判定）：
- 每個個體：整合次數、各做法的提案數、閘門判斷的分布、採用的版本與字數增減、行數（procedures-v1 的表）；每一次重複的 HP1～HP3；
- **雜訊的數值對照**：閘門的每個處境，現行做法兩個輸出之間的文字距離（1 − 二元組 Jaccard），提案的輸出與兩者的平均距離；
  個體判斷「大於雜訊」的處境，距離的超出量是否比較大（AUC；包括 procedures-v1 的三格）；
- **閘門的成本**：每個有雜訊基準的判斷的呼叫數；只看第一個處境、沒有大於雜訊就停時，會改變結論（adopt 或 revise）的判斷數；
  閘門占輔助呼叫輸出 token 的比例；
- 花費（`experiments/eval/cost.ts`）。

## 限制

- 每段歷史 3 次、9 次對話；模擬使用者與個體都是 deepseek-flash；judge 是另一個模型，但同一家。
- judge 看得到修改中的具體話題，提示詞只能要求它看方向。
