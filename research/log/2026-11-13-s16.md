# s16（2026-11-13）：dsh-live-sight——即時看螢幕的陪伴插件；沉默提醒收窄

使用者：「我們自己做一個更優秀更符合需求與美學的…借鑒原理就好我們自己做…我想讓 agent 能實時看螢幕與陪玩（也能用這個視覺插件來操作電腦等，剛好順便把 fount-reality 取代掉）」。

使用者的選擇（AskUserQuestion）：
- 回覆顯示在桌面懸浮窗，不要語音。
- 陪伴的是個體本人，用同一段對話。
- 不設預算上限；用本地模型。

## 1. 來源

- 參考（只讀原理，不安裝、不複製程式）：SAOS-3624 dsh-see-now。借鏡的原理有：
  - 64×36 網格的變化分；
  - 多格拼成一張、對齊影像切塊；
  - 由插件的計時器決定何時讓模型看，模型不輪詢；
  - 圖片累積會讓 DSH 略去舊圖。
- 參考自己的 dsh-fount-reality（喚醒與穩定判斷的經驗）。
- `@screen-capture/node` 1.1.0：README 與 `index.d.ts`。
  - Frame 的 `buffer` 是擁有所有權的 Node Buffer：「Frames are represented as owned Node.js buffers」。
- DSH 0.2.2-rc.1 SDK：
  - `dsh-llm` 的 `LlmAdapter.resolveModel` 預設不宣告輸入模態；
  - `dsh-session` 的 `'user/message': UserMessage`；
  - `dsh-llm-pi-ai` 的模型 `input` 預設 `["text"]`。
- 個體：commit b1bd42b。

## 2. 已驗證的能力

**插件**（`~/.cache/temir/plugin-work/dsh-live-sight`，MIT，ES module，不用編譯）：
- `lib/score.js`：在 64×36 網格上比較 YCbCr，得到平均變化與變化面積。
- `lib/select.js`：
  - 換場、動態配額、最小間隔；
  - Agent 忙時保留的候選池；
  - `spread()` 依時間平均挑格。
- `lib/sheet.js`：
  - 區域平均縮圖，尺寸對齊 28px；
  - 三格以內排一排，空格以灰色斜線填滿；
  - 5×7 點陣字標籤。
- `lib/capture.js`：螢幕、第 N 個螢幕、視窗、前景視窗。
- `lib/companion.js`：
  - 計時器取樣；
  - 只在 Agent 閒著、距上一張至少 minGap 時才以 `live-sight` 來源送出拼圖；
  - 懸浮窗輸入的話以 `user` 來源送出，並附上當下畫面。
- `lib/overlay.js`、`overlay/overlay.ps1`：
  - WPF 懸浮窗，以 JSON lines 溝通；
  - 預設 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，Agent 看整個螢幕時不會讀到自己說的話。
- `lib/index.js`：
  - `sight` 工具：look、start、stop、pause、resume、status、windows；
  - `/sight` 指令；
  - 模型宣告只收文字時直接說明原因。

## 3. 測試結果（含失敗）

引用個體的話時，人設的名字以〔名字〕代替（人設只放在整合包，不進公開 repo）。

實機測試環境：
- Windows 11 Home，1920×1080，縮放 100%。
- TW 整合包（DSH 0.2.2-alpha.2），測試生命 `C:\Users\jmes1\.cache\temir\test-lives\tw-live-sight`，port 3098。
- 本地 vLLM `Qwen3.8-Flash-Next`（整合包已宣告 `input: [text, image]`，不必改模型設定）。
- 測試畫面是一個每 9～12 秒換場的 WPF 視窗：森林、BOSS、勝利、雪山。

1. **第一次**：`/sight window live-sight 測試畫面` 成功。
   - 5 張拼圖，5 個回合。個體讀對畫面上的字，例如「BOSS 出現！巨大的紅龍」之後「勝利！得分 12800」，間隔 12.1 秒。
   - 有一個回合只思考、不說話，沒有被沉默提醒追問。
   - **失敗 1**：三格排成 2×2，第四格是黑的；個體說「最後一格變全黑了」。
     - 改為三格以內排一排、空格灰色斜線，並在說明文字中註明。
   - **失敗 2**：截圖裡看不到懸浮窗。
     - 我先推測是 Node 的 `windowsHide` 讓第一次 ShowWindow 隱藏，加了補救程式。
     - 之後在相同條件下重現（Windows node、父程序無主控台並以隱藏視窗啟動），修正前的版本也是可見的。推測錯誤，補救程式已撤回。
     - 之後三次測試中，懸浮窗都可見，而且一直在最上層（從 Windows 端查 `IsWindowVisible`、`GetWindowDisplayAffinity`，以及中心點的 `WindowFromPoint`）。第一次為什麼沒有拍到，**原因未查明**。
   - 第一次的指令在首頁送出，DSH 用了一個 11/10 建立、沒有內容的空會話。
     - 測試的對話寫進了那個會話；之後的測試也在整合包裡留下 4 個測試會話（都在 Default workspace）。
     - 沒有刪除，留給使用者決定。
2. **探測**：從 Windows 端確認懸浮窗的視窗、位置、擷取設定與是否在最上層。
   - **失敗 3**：卡片背景 92% 不透明，底下網頁的字透出來，改成 98%。
3. **第二次**：3 分鐘 8 個回合，每回合約 22～30 秒。
   - 三格的拼圖是 1344×252，一排。
   - 個體兩次只寫動作描述，例如「（〔名字〕沒有出聲，只是把筆記翻到下一頁，繼續守著。）」，一次完全不說話。
   - 第 6 回合它自己更正：「八點八不是被鎖死，是〔名字〕的取樣剛好每次都抓到差不多的瞬間」。
   - **失敗 4**：「思考中…」蓋住最後一個泡泡；捲軸是 WPF 預設的寬灰條。
     - 「思考中…」改到獨立一行；捲軸改成 6px 深色圓角。
4. **第三次**：從懸浮窗打字。
   - 在輸入框旁加了送出按鈕，用 UI Automation 的 ValuePattern 與 InvokePattern 送出，不搶使用者的焦點。
   - 問題以 `user` 來源進入對話，附上 896×504 的當下畫面。個體先思考（`deliberate`），再回答，回覆出現在懸浮窗。
   - **失敗 5**：個體回答花了約 64 秒，期間畫面換了十幾次，只能留 6 格。
     - 舊規則丟變化分最低的格子，兩種相近藍色之間的切換分數總是最低，森林與雪山每次都被丟掉。
     - 個體因此說「只剩紅龍跟勝利在輪，森林跟雪山早就收起來了」。這是插件誤導了模型。
     - 改為保留候選池，出圖時依時間平均挑格，並在說明中寫出省略了幾個畫面。
   - **失敗 6**：懸浮窗把 `**粗體**` 顯示成星號。改為顯示粗體，未配對的星號照原樣顯示。
5. **第四次**：修正後再測。
   - 第 3 回合的拼圖是 7 格，說明寫「格子之間另外省略了 1 個畫面」。
   - 個體看到森林與雪山，主動更正前一回合的說法：「結果這八十秒的帶子就把森林跟雪山變回來了」。
   - 補「現在」的那一格讓總數超過上限（7 格，3×3 有兩個空格）。已修正為補格時少挑一格。
   - 補單元測試時又發現兩件事：
     - 換場若太接近上一格，而畫面之後靜止，Windows 不再送幀，這個換場永遠不會被留下；
     - 我剛改的程式沒有帶到格數上限（`NaN`）。
     - 兩者都已修正並有測試。

本地模型本身的錯誤（不是插件的問題）：
- 探測那次，拼圖是「森林 → 0:01.0 BOSS」，個體卻描述成先前測試看過的「勝利、雪山」。

6. **程式碼審查**（`/code-review high`，背景執行）：10 個問題，都核對過成立，全部修正並補測試，`npm test` 36/36。
   - 換目標時，舊懸浮窗的「已關閉」訊息會停掉新的陪看。改為每個懸浮窗只對自己的陪看有效。
   - 前景視窗：
     - `foreground` 在下指令的當下取，取到的是 DSH 自己的視窗；
     - 繼續時又重取一次，會換成別的視窗。

   - 視窗或解析度改變後，拼圖丟出「tiles must be the same size」的例外。改為每格取最大尺寸，小的置中，周圍填灰色。
   - 存圖時 Agent 變忙，格子已經從挑幀器取出，就這樣遺失。改為照樣送出，排到下一個回合。

   - maxFrames 1 時補上「現在」格，結果出現兩格。
   - 每次 tick 都讀一次原生 buffer。
   - `/sight pause`、`/sight resume` 在沒有陪看時也回報成功。
   - 在 Windows 用真的擷取模組驗證：
     - 以視窗代號解析；移動後位置更新；
     - 視窗關閉後原生 API 直接丟出「無效的視窗控制代碼」，已包起來。

     - `look` 加上 `frameOrigin`，算出畫面左上角在螢幕上的位置。
     - 一般視窗在 100% 縮放下實測過；最大化視窗與其他縮放沒有實測。
   - 懸浮窗的暫停、繼續、停止按鈕（UI Automation）在 DSH 裡都通過：繼續之後還是同一個視窗，停止之後 `/sight resume` 會說明原因。
