# ADR-0008：思考、扣除、比對、整合、念頭的做法屬於個體自己（2026-10-30）

- 日期：2026-10-30

  - 單元測試；e2e-40、e2e-40b、e2e-41（DeepSeek）；dev15 沒有退化（`experiments/results/dev15-report.md`）。
  - 長一點的生活中的觀察：`experiments/specs/procedures-v1.md`。

  - 使用者 2026-10-30：「人格這東西要塑造就不能用一堆固定的東西你根本不了解」；「你假裝明白有用嗎?根本沒用心去理解整個理論與那些參考用的DSH插件, 甚至是論文都沒有看」。
  - 重讀之後的整理見 `research/reading/2026-10-30-synthesis.md`。
  - 使用者對那份整理的兩個問題的回答：「思考、扣除、比對、整合、念頭的做法，全部交給個體修訂」；「做法的第一版由誰寫:你」。
- 假說：`research/pc-theory/hypotheses.md` H-P。

## 問題

1. **類別是寫死的。** 以下都是程式寫死的分類，模型只能照我的定義歸類，個體改不了：
   - 7 類做法種類（`rd/aux.ts` 的 KINDS），D22 還把它改成強制作答；
   - 4 級重要程度（`self/state.ts` 的 SIGNIFICANCE）；
   - 3 類懸念與一長串「不算」的規則（`rd/memory.ts` 的 LeftType、`rd/aux.ts` 的事後比對提示）；
   - 主動開口每 24 小時最多 3 次（`thought/thought.ts` 的 INITIATIVE_PER_DAY）。
2. **會變的只有內容，做法從不改變。**
   - 思考、扣除、比對、整合、念頭的提示都寫在程式裡。
   - 個體能修訂自我模型、敘事、目標、看法、技能，但不能修訂自己怎麼思考、怎麼評價。
   - 理論性質 2：「PC 影響思考、行動及經驗評價，經驗與決策又反過來改變 PC」。Memory-Centric CL（arXiv:2610.29357 §Open Challenges）：「Feedback simply changes memory content ... while the policy itself stays fixed」。

## 決定

### 1. 做法與程式的分工

每一次輔助呼叫的系統提示由三段組成：

| 段落 | 誰的 | 內容 |
|---|---|---|
| 框架 | 程式 | 一句話說明這是哪一個步驟（例如「對方剛說了話，你在回應之前先思考與準備」），以及深度整合這類由機制觸發的情形 |
| 做法 | **個體** | 第一人稱的做法說明：怎麼看、怎麼想、怎麼判斷、什麼算數。第 N 版，可以修訂 |
| 輸出 | 程式 | 機制需要的欄位、型別與必答的判斷（規則 2 的強制判斷）。程式只驗證結構，不驗證內容屬於哪一類 |

- **做法有五個**：
  - 思考（`deliberate`）：思考的提示；
  - 扣除（`subtract`）：思考中的扣除，以及扣除的強制判斷（D20 第三版）；
  - 比對（`outcome`）：事後比對；
  - 整合（`integrate`）：一般與深度整合；
  - 念頭（`thought`）：閒置時的念頭。
- **程式只保留結構性的保證**：
  - 生命日誌只增不改；
  - 強制判斷的驗證與重問（規則 2）；
  - 理論規定的判準：自我修復的穩定性與適應性兩者缺一不可（性質 6），由程式確認兩者都有判斷；
  - 安全與機密，以及不會連發訊息的保證（第 4 節）。

### 2. 拿掉寫死的類別

每一項都改成「程式決定何時需要判斷，模型逐項作答」，內容用個體自己的話：

| 拿掉的 | 原本的用途 | 改成 |
|---|---|---|
| 做法種類 KINDS（撤回 D22） | 扣除需要判斷時，找同一類的經驗（`exclusionReviews`） | D23 的逐筆經驗判斷再加一項 `sameExcluded`：這次的哪幾個做法，和那次扣除的做法實質上相同。只在那筆經驗有扣除時必答。<br>需要判斷的扣除：被扣除的做法在 `sameAction` 或 `sameExcluded` 中出現過的經驗 |
| 重要程度 SIGNIFICANCE | 不是日常的才寫成感受紀錄；「轉折」觸發深度整合；「值得注意」以上的預測落空成為意外 | 三個布林判斷：<br>`keepFeeling`：要不要把這個感受記下來，日後回憶時會帶出；有感受時必答。<br>`reconsider`：這段經歷要不要讓我現在就重新檢視自己，也就是深度整合；必答。<br>`gapOnMind`：預測與實際的落差會不會一直掛在心上，也就是意外；matched 是 no 時必答 |
| 懸念的 3 種類型 | 向外（答應的、在等的）列在前面，不被向內的事擠掉 | 每件懸念必答 `forOther`：它推動我對對方做什麼（true），還是推動我自己的反省（false）。什麼算懸念、什麼不算，寫在比對的做法第一版中，可以修訂 |
| 每 24 小時最多 3 次主動開口 | 主動開口的排程 | 念頭的輸入列出事實：最近一次主動開口的時間、之後對方有沒有回話、24 小時內開口幾次。要不要開口由念頭的做法判斷（第一版寫著「一天之內不要說太多次」） |

- **處境的格式**：「對方：…｜對方的意圖：…｜…」不再由程式規定，改成思考做法第一版裡個體的習慣。
  - 依據：JitRL 的 State Construction，「功能相同的處境映射到相似的表示」。
  - 程式只在處境有這些欄位時，以三個欄位計算詞彙相似度（`stateTerms`），否則用全文。
  - 個體逐筆判斷的同類處境（D23 的 `sameSituation`）不受影響。
- **舊紀錄**：相容。`kind`、`didKind`、`significance`、`LeftType` 照舊讀得懂；新紀錄不再寫。

### 3. 做法的版本與修訂

- **紀錄（都只增不改）**：
  - `self/procedure`：採用的版本 `{name, version, text, reason, source: creator|self, proposal?}`。
  - 第一版由創造者撰寫，對應使用者的回答「做法的第一版由誰寫:你」。
    - 個體啟動時，沒有這個做法的紀錄就寫入第一版（`temir-self`，與初始人設相同的時機）。
    - 之後程式的預設文字再改，也不會改到已經存在的個體。
  - `self/procedure-proposal`、`self/procedure-probe`、`self/procedure-decision`：提案、探測與帳本。
- **提案**：整合時提出（整合的輸出多一項 `procedures`）。
  - 每項寫出完整的新版本、理由、依據的經歷，以及穩定性與適應性。
  - 與目標、看法相同：兩項判準都成立、也都有證據，才進入閘門；否則保留為提案。
  - 整合的輸入列出目前的五個做法（全文與版本）和帳本的最近幾筆，所以被否決過的提案看得到（WikiSkill 的 skill-impact）。
- **閘門：Propose–Probe–Compose**，依據 Harness² §Task-Level Recursion：沒有對照就直接修改會變差。
  - **Probe**（第二版，2026-10-31）：
    - 處境：先取提案依據的經歷所在的那幾次真實呼叫（`memory/aux` 中記下的輸入），再取最近的，最多 3 個。第一版是最近的 2 個。
    - 每個處境有照現行做法的**兩個**輸出，加上照提案做法的一個；系統提示的其他兩段相同，照那次呼叫的設定（深度整合、消融）組出。
    - 照現行做法的輸出能重用就不重跑：那次真實呼叫本身（`memory/aux` 記下系統提示的雜湊；雜湊、模型都相同、而且那個輸入只呼叫過一次），
      以及之前的探測照同一個現行系統提示跑過的輸出。同一個提案的第二輪只跑修改後的版本。
    - 思考與扣除的探測，附上那一次之後實際發生的事（那個決定的事後比對）。
  - **Compose**：個體看著每個處境的輸出，決定 adopt／revise／reject，每個理由都要指出處境 S1、S2… 與看到的差異。
    - **雜訊**（第二版）：每個理由必答 `beyondNoise`：這個差異是否大於照現行做法兩個輸出之間的差異。adopt 至少要有一個理由是 true，
      否則重問（規則 2）。依據 RRSI：改進要大於雜訊才接受。個體沒有可重複評估的任務集，量不出數值的 δ，這是同一個處境上的定性比較；
      帳本記為 `gate: noise`（第一版的紀錄是 contrast）。
    - 判斷不合格時重問一次（規則 2）。
    - revise 時，修改後的版本再探測一輪；每次整合最多一輪。
  - 沒有可以探測的真實呼叫時，記為 unprobed，不採用。
  - 帳本記下這一輪的模型呼叫次數（`calls`）與重用的輸出數（`reused`）。
- **中斷**：閘門中途被程序結束打斷時（e2e-40、dev15），提案留著沒有決定。
  - 下次整合時接著對照：這次的新提案優先，沒有新提案時對照最舊的未決提案。
  - 啟動時，若有整合時提出、還沒有決定的提案，也接著對照（`temir-integrate` 的 `startPendingGate`）。
  - 實驗的沉澱階段會等這種提案決定（`experiments/runner/run.ts` 的 `pendingProcedures`）。
- **編輯預算**：每次整合最多一個做法的提案進入閘門（WikiSkill 附錄 Algorithm 1：每輪一個原子提案）。
  - 帳本記下成本（文字增減的字數），依 RRSI 附錄 Algorithm 1、2。
  - 個體沒有可重複評估的任務集，量不出雜訊下限 δ，所以閘門標明「未經量測」，與技能相同（ADR-0003）。
- **紀錄可追溯**：每次輔助呼叫的 `memory/aux` 記下用了哪幾個做法的哪一版。

### 4. 主動開口與念頭的排程

- 程式保留一條保證：上次主動開口之後，對方要先說過話才能再開口。
  - 這是防止連發的安全保證，不是人格：沒有它，對方不回話時，每段閒置都可能再發一次。
  - 使用者若認為這條也該交給個體，再改。
- 每 24 小時最多 3 次的上限拿掉，改成念頭的輸入中的事實與念頭做法的第一版。
- **念頭的排程**（2026-10-31，e2e-40 的問題）：
  - 以前「上次念頭之後有任何新事件」就會再想一次，閘門每寫一筆探測就觸發一次念頭，9 次念頭多半在想同一個打算。
  - 改成只看新的經歷：對方或我說的話、事後比對、整合、做法的新版本（`thought/thought.ts` 的 `EXPERIENCE_KINDS`）。
    念頭本身、它的感受紀錄、輔助呼叫、閘門的探測不算。這是排程，不是人格；程序重啟之後從生命紀錄接著算。
  - 同一個打算一直換寫法累積：念頭有打算時必答 `replaces`（這個打算取代了哪幾件懸著的事），被取代的不再列出。

## 不在這次範圍內的

- **其他提示照舊由程式提供**，例如回憶的事實萃取、記憶分區、技能的回顧與合成、插件。使用者列的是思考、扣除、比對、整合、念頭。
- **把判斷放回主 agent 自己的脈絡**（synthesis §3 第 3 點）：2026-10-31 做成可切換的條件（`temir-rd` 的 `mode: context`），
  見 `experiments/specs/context-v1.md`。context 模式中，閘門仍以輔助呼叫重跑思考（近似）。
- **消融的限制**：energy、subtraction、perPerson、revision 的消融拿掉的是輸出段的欄位。
  - 做法段中提到被消融機制的句子，用固定的行首或關鍵詞過濾。
  - 做法被修訂過之後，過濾只能盡力而為。之前的消融實驗都是在第一版之前做的。
