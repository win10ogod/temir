# ADR-0004：對方沉默時的暫時比對與主動開口（plan v2 M4）

- 日期：2026-10-29
- 狀態：已實作。單元測試；e2e-25～29（DeepSeek）。
- 觸發：使用者 2026-10-29：「盡可能全力改善並實現原始設計的要求」。plan v2 M4 的「閒置時的自主認知與自發行動（`agent.followup`、排程）」只完成了念頭，沒有行動。

## 問題

1. **最後一回合的承諾不算數。**
   - 事後比對只在對方下一句話來時才做（`temir-rd` 的 `agent/pre-step`）。
   - 對方說完就離開時，個體在最後一回合答應的事不會成為「懸著的事」，閒置時的念頭看不到它。
   - e2e-25：對方請它一分鐘後提醒關火，然後再也沒說話，`rd/outcome` 一筆也沒有。
2. **念頭只能留下打算，不能行動。**
   - 念頭的打算要等對方下次開口才可能兌現；
   - 個體沒有辦法主動說話。

## 決定

1. **暫時的比對**（`temir-rd`，`silenceMinutes`，預設 10）。
   - 對方在我回覆之後沉默這麼久，最後一個決定先以「對方到現在都沒有再說話」比對，記為 `provisional`。
   - 這一回合答應的事因此成為懸著的事。
   - 對方之後回話時，`openDecision` 仍視它為未比對，會再正式比對一次；`experiences()` 對同一個決定以最新的比對為準。
2. **主動開口**（`temir-thought`，`spontaneous`，預設開）。
   - 念頭的輸出多一個 `now`：要不要現在就主動對對方說，由個體判斷，只有布林 true 算數，沒有打算時無效。
   - 決定現在說時，在最近一段對話中以 DSH 的 `agent.followup` 開始一個由念頭發起的回合。這與 `dsh-tool-jobs` 叫醒閒置 agent 的方式相同：`ctx.get('agents')?.get(id)`，`status === 'idle'` 時 `followup`。
   - 該回合的輸入以 `temir-thought` 為來源，寫明「這不是對方說的話」，以及念頭與打算；RD 與回憶只處理對方的話，不會把它當成對方的話。
   - 每次都記下 `self/initiative`，包括送出與否、沒送出的原因（對話已經不在、正在進行中、排程規則）。
3. **排程規則（`mayInitiate`，不是人格參數）**：
   - 上次主動開口之後，對方要先說過話：不連續追著對方說。
   - 24 小時內最多 3 次。
   - 要不要說、說什麼，仍由個體在念頭中決定。

## 驗證

- 單元測試：
  - `now` 的解析與記錄；
  - 排程規則：不連續追著說、24 小時上限、時間過後恢復；
  - 暫時比對後，對方回話仍會正式比對，而且以最新的比對為準。
- e2e（DeepSeek，計時縮短的測試設定）：

| | 情境 | 結果 |
|---|---|---|
| e2e-25 | 「一分鐘後提醒我關火」 | 個體自己用 DSH 的排程工具，一分鐘後送出「該去廚房關火了」：身體本來就有的主動能力。這次也發現了問題 1 |
| e2e-26 | 「想到貓的名字再告訴我」 | 暫時的比對記下承諾；念頭浮上這件事，留下打算，個體判斷「現在先不該急著交答案」，`now`＝false |
| e2e-27 | 「想到就馬上傳給我」 | 個體當場就給了名字；念頭判斷該做的已經做了 |
| e2e-28 | 「吵完架，我先冷靜一下」 | 念頭：「等待也是一種在場，不必用追問去證明我在意」，不開口 |
| e2e-29 | 送出的機制 | 以只在這次載入的測試插件代替模型寫下 `now`＝true 的念頭，送出走正式的 `deliverInitiative`：agent 是閒置的，followup 開始新的回合，個體主動說了「再次推薦一次。柳丁……」 |

- **未驗證**：由真實的模型判斷決定開口、並且送出。三個情境中個體都選擇不打擾，這是它自己的判斷；這條路徑的每一段都已分別驗證過。

## 限制

- 只會在「最近一段對話」開口；沒有其他通道（Telegram／LINE／Discord 插件仍未做）。
- DSH 的程序要還在、那段對話的 agent 還在記憶中。一次性的 headless 執行沒有閒置時間。
